Stageflow · a plain explanation

Memory is a notebook that stays.

An agent forgets when its conversation ends. The next run starts blank. Memory is the notebook it can open again.

Why a blank start is a problem

Two jobs that repeat. Today, each run only knows what you told it this time.

Pipeline

Hiring search

Last week the pipeline looked at a hundred people and kept ten. Next week, for a different job, it starts from zero and is likely to find the same people again. It has no memory of the pool it already built.

Agent

Refunds

One conversation approves a refund for a customer. A later conversation, even with the same agent, does not know that. It can approve the same refund again.

What we give it

A named notebook, kept by Stageflow, not inside one run. A pipeline or an agent is pointed at that name. While it works, it can read the notebook and write in it. You can open the same notebook and read it.

  1. 1
    You create a memory and give it a name, such as candidate-pool.
  2. 2
    You attach that name to a pipeline or an agent. The run does not contain the notes. It only knows the name.
  3. 3
    During the run it can read what is there and replace it with a new version. The next run, or another session, sees the new version.
  4. 4
    If the name is missing, the run does not start. Stageflow checks first.

Two kinds of notebook

Same idea, two shapes. We build the page first. The cabinet is the later shape, for when the notes become a list you have to look through.

Build this first

A single page

The agent reads the whole page and can rewrite it. Good for a short note: rules, a scratch summary, a few facts that always matter.

candidate-pool Searched 100 people in March. Kept 10 for the designer role.
Add later

A filing cabinet

Each person, or each refund, is its own card. The agent looks up one card instead of rereading everything. Old cards stay, so a decision is not erased by a rewrite.

How the page can become a cabinet

The memory is the name. The page is only what that name holds today. Later, cards sit beside the page. The name does not change, and pipelines that already point at it do not change.

one folder · candidate-pool

The page

A markdown note. Today this is the whole memory. Later it can stay as the cover sheet: a short summary on top of the cards.

The cards

Not built yet. Room is left in the same folder. Each card is one person, one refund, one fact you can look up.

Now: read, replace The stage asks Stageflow for the page, then hands back a new page. It never gets the file itself.
Later: look up, add Same name. Two new actions. Look up a card. Add a card. The page actions still work.

The one way this gets stuck

If we hand the agent the file and let it edit that file directly, the memory is the file. There is nowhere to put cards later without changing every pipeline that uses it. Stageflow has to be the one reading and saving, so a cabinet can show up behind the same name.

The notes live in Stageflow’s data directory, so they stay when a run ends, and when the app runs in Docker, as long as that directory is kept.
