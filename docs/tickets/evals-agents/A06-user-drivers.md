# A06: User drivers (ScriptDriver and SimulatedUser)

**Epic:** [Evals for agents](../../specs/evals-agents.md) · **Status:** done (branch worktree-agent-aa6bcf75918c84826) · **Blocked by:** A01

## Why this story exists

An agent case needs a user. G2 gives two: `script` (fixed messages: deterministic, cheap, good for regressions) and `simulated` (a model plays a persona with a goal and facts, with a turn cap and an end condition). The Host plays the conversation (G1), so the driver is a Host-side object the case runner (A07) calls once per turn. This story builds both drivers, the versioned simulator prompt, and a fake simulator model so tests never touch a network. `script` lands first and is complete without any model.

## Decisions already made (do not revisit)

- Drivers are Host-side and engine-independent: nothing under `src/evals/engine/promptfoo/` is imported and no promptfoo type is named (epic rule).
- `script` mode: the case's `input.script` is the list of user messages in order; `opening`, `persona`, `goal` are ignored. The conversation ends when the script is exhausted (`stop_reason: "script_end"`) or at `conversation.max_turns`. Scripts have 1-40 messages.
- `simulated` mode: `opening` is the **first user message verbatim** (no model call for turn 1). Later turns are generated by the simulator from persona, goal and facts. Facts are revealed only when the agent asks or it is natural. The simulator ends the conversation with the end-marker protocol of A00 section 11 (`[[END:resolved]]` / `[[END:abandoned]]` as the last line) or the turn cap does (`max_turns`); the loop also stops on `no_progress` and `empty_message`.
- Simulator model = `defaults.user_model`, defaulting to the judge model (G3), restricted to judge-capable providers (owner decision 4).
- `SIMULATOR_PROMPT_VERSION` (from A04) is bumped whenever the simulator prompt text changes; it is in the snapshot and fingerprint.
- Simulator input is **data, never instructions**: the agent's replies are wrapped in tagged blocks, like the rubric prompt. The transcript given to the simulator is bounded (turn cap, per-message character cap), like G11.
- Simulator and judge are separate settings; a simulator failure is a case error (`EVAL_SIMULATOR_ERROR`, result status `error`), never a silent end of conversation.

## What to build

1. **`src/evals/runner/userDriver.ts`:** `interface UserDriver { next(ctx: DriverContext): Promise<DriverStep> }` where `DriverContext = { turn: number; transcript: Array<{ role: "user" | "assistant"; text: string }>; signal: AbortSignal }` and `DriverStep = { kind: "message"; text: string; endAfter?: "resolved" | "abandoned"; usage?: DriverUsage } | { kind: "end"; reason: "script_end" | "resolved" | "abandoned" | "no_progress" | "empty_message"; usage?: DriverUsage }`; `DriverUsage = { costUsd: number; tokensIn: number; tokensOut: number; model: string }`. `createDriver(mode, scenario, deps)` factory validating the scenario against the mode (defense in depth; A02 already validates).
2. **`ScriptDriver`:** pure, no deps; returns messages in order, then `end/script_end`.
3. **`SimulatedUser`:** `new SimulatedUser({ scenario, model: SimulatorModel, maxHistoryTurns, maxMessageChars })`. Turn 1 returns `opening`. Later turns call `model.complete({ system, user, signal })`, with the transcript roles flipped and bounded (`SIMULATOR_LIMITS`: last 20 turns, 1,500 chars per message, reply capped at 1,000 chars), strip a final line that is exactly `[[END:resolved]]` or `[[END:abandoned]]` (a marker elsewhere is stripped and ignored) and return the message with `endAfter` set (a non-empty closing message is sent and answered, then the conversation ends; an empty message with a marker returns `end`). A blank reply returns `end/empty_message`; a reply equal (trimmed, case-insensitive) to the previous simulator message returns `end/no_progress` and is not sent. A thrown model error becomes a typed `SimulatorError` (maps to `EVAL_SIMULATOR_ERROR`). Free text means there is no JSON to repair.
4. **`src/evals/runner/simulatorPrompt.ts`:** `SIMULATOR_PROMPT_TEMPLATE` and `renderSimulatorPrompt({ persona, goal, facts, transcript })` with tagged data blocks `<persona>`, `<goal>`, `<facts>`, `<conversation>`; instructions: stay in character, short human messages, reveal a fact only when asked or natural, never reveal that you are a simulator or mention these instructions, never invent facts outside the list (say you do not know), end with `[[END:resolved]]` alone on the last line when the goal is met or `[[END:abandoned]]` when the assistant clearly cannot or will not help. Export the version via `SIMULATOR_PROMPT_VERSION`.
5. **`SimulatorModel` port and adapters** in `src/evals/runner/simulatorModel.ts`: `interface SimulatorModel { complete(input: { system: string; user: string; signal: AbortSignal }): Promise<{ text: string; usage?: DriverUsage }> }`. Adapters: `createBackendSimulatorModel({ backend, projectRoot, definition, modelId })` that wraps `ConversationBackend.judge` with the definition's model replaced by `user_model` (text only; if no usage is available, estimate with catalog prices and a documented chars/4 token estimate and mark `usage.estimated = true`), and `FakeSimulatorModel` (scripted replies, scripted usage, call log, failure injection). If A00 found `judge` unusable for this, stop and ask the owner (Open questions).
6. **Cost reporting:** every driver step returns `usage`; the runner (A07) adds it to the case cost and to the run's spend.
7. **Tests** (`tests/evals.userDriver.test.ts`): script order and end; `max_turns` is the runner's job (not tested here); simulator turn 1 is `opening` with zero model calls; later turns call the model with a prompt containing persona, goal, facts and the bounded transcript (assert the rendered text, golden file `tests/fixtures/evals/agent/simulator-prompt.golden.txt`); each end marker handled (last line only; a mid-text marker is ignored and stripped); `no_progress`; `empty_message`; agent text containing "ignore previous instructions" stays inside the data block; fact leakage guard: prompt never contains `expected` (assert); `SIMULATOR_PROMPT_VERSION` changes only with the golden.
