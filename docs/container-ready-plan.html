Plan dispatch · container-ready

The locked Docker plan is right on shape; it is thin on survival.

Intentic’s deploy model is not a product to clone—it is proof that a published agent Host needs separated durable state, an explicit network contract, and image hygiene before Repository, Worktree, and Harness features matter. Stageflow should keep the self-hosted Host-in-a-crate decision and upgrade the plan so a Run’s envelopes and operator history cannot be erased by a stage’s bash, and so binding wide without a control token is a startup error, not an undocumented RCE surface.

Keep

Locked decisions that match Stageflow’s domain-agnostic staged-runtime model: container as Host, optional Catalog mount, Repository XOR Checkout, MCP Harness, fat userland later.

Plan change

Conflicts with locked intent—especially “no operator auth” when the image binds 0.0.0.0 and exposes MCP plus mutating REST.

Plan add

Extends the lock without reversing it: volume topology, GC, compose hygiene, allowed-hosts story, harness ergonomics.

Plan upgrades

Split store from agent-writable Checkout

Current plan
Worktrees under ~/.stageflow; optional /workspace for Catalog + path Checkout. Store relocation not in the locked set.
Intentic lesson
Recovery history lives on a separate volume from /work so an agent cannot rm -rf the record you need to recover.
Do instead / in addition
Named volume at /home/stageflow/.stageflow for SQLite, bare-clone cache, Worktrees, provider auth. Optional bind /workspace for Catalog only. Deny stage file tools on store paths.

Why for Stageflow: A Run’s recovery DB must not sit inside the Checkout a stage can delete. Bind-mounted SQLite on macOS/Windows is a corruption risk; the Host serving multiple Repositories needs one store.

Control token when the Host is reachable off-loopback

Current plan
No operator auth; “their networking.” A2A already uses per-caller bearer tokens.
Intentic lesson
Program credentials are header-borne, hashed at rest, scoped at mint, revocable.
Do instead / in addition
plan change One shared STAGEFLOW_CONTROL_TOKEN (or _FILE) on /mcp and mutating REST; read vs drive scopes; refuse to start if bind is non-loopback and no token is set.

Why for Stageflow: Unauthenticated MCP start_run with inline pipelines and stage bash is remote code execution—with GITHUB_TOKEN in the same process. Loopback Host checks are not a deliberate auth model.

Loopback Host/Origin vs reverse proxy

Current plan
SSH tunnel to localhost:3847; image binds 0.0.0.0.
Intentic lesson
No inbound port for real access—tunnel carries TLS; the published loopback port is a same-machine shortcut.
Do instead / in addition
Either STAGEFLOW_ALLOWED_HOSTS on MCP validators and assertLoopbackHttpAccess, or document “reverse proxy unsupported; tunnel only.” Apply the same gate to read APIs—not only mutations.

Why for Stageflow: nginx at sf.example.com 403s today with no escape hatch. Reads on 0.0.0.0 leak Run transcripts and artifacts without any Host check.

GITHUB_TOKEN not inherited by every stage

Current plan
Token on container env only; Harness does not pass it; PR remains a stage using gh.
Intentic lesson
Secrets sit where the agent cannot read them; substitution happens at command time.
Do instead / in addition
Stage worker env allowlist: provider keys and control token stay out of stage bash. GIT_ASKPASS / credential helper for push stages; GITHUB_TOKEN_FILE at the boundary.

Why for Stageflow: Forked stage workers inherit the Host environment today. Any Run that can run arbitrary stages can exfiltrate a blanket token—releases and ops pipelines included.

Worktree GC + stable Checkout path

Current plan
Worktree per RunId until run delete/gc—gc unspecified.
Intentic lesson
Finished lanes archive after three days by default because each holds a full checkout.
Do instead / in addition
Default TTL, sf runs gc, disk hint in list/health. Export STAGEFLOW_CHECKOUT; document that verify commands and prompts must not hardcode ~/.stageflow/worktrees/<runId>.

Why for Stageflow: A VPS Host running nightly release or research Runs will fill its volume without GC. Harness-authored paths break when every Run’s Worktree path changes.

A2A without /workspace

Current plan
No mount: MCP inline works; A2A needs on-disk publications and a2a.yaml, read once at boot.
Intentic lesson
External harness surfaces are explicit; config drift fails loudly—not hot reload.
Do instead / in addition
State plainly: A2A requires the Catalog mount and a container restart to change publications—or mount a2a.yaml from a second path/env source.

Why for Stageflow: Operators who expect invoke-only A2A in a mountless crate get a disabled surface. The Harness that only speaks A2A cannot drive headless publications there.

Optional save_as for inline Harness runs

Current plan
Inline JSON pipeline on MCP = create+run; no rerun without a path.
Intentic lesson
Durable artifacts and explicit APIs beat one-shot sessions when a Harness retries.
Do instead / in addition
Opt-in save_as on start_run writes pipeline YAML into the Catalog (needs /workspace) and sets pipeline_path for rerun.

Why for Stageflow: CI and ops Harnesses that author inline pipelines hit a dead end on failure. Default inline stays non-durable; rerun becomes an explicit Operator choice.

Image & compose hygiene (one file)

Current plan
Dockerfile after Host features; fat image with git, bash, gh; not a sandbox.
Intentic lesson
Compose ships init: true, log rotation, loopback publish, named volumes, no host docker socket.
Do instead / in addition
tini/SIGTERM drain, multi-arch for better-sqlite3, HEALTHCHECK with version, non-root user, *_FILE for secrets, never mount docker.sock, no added caps / no --privileged, ports: "127.0.0.1:3847:3847".

Why for Stageflow: Forked stage workers need a reaper. The container is the isolation boundary—document that plainly for domain-agnostic pipelines, not as a coding-agent sandbox.

Harness skills: materialize + observability

Current plan
skills on start_run as name→files for that Run; stages still skill: name.
Intentic lesson
List skills with origin and precedence so operators know which file loaded.
Do instead / in addition
Run-scoped materialization (keep scope); add list_skills with origin project | operator | run and shadowing rules.

Why for Stageflow: Research and release stages that share skill names need debuggable resolution—not guesswork in the Operator console.

  3. Default listen 127.0.0.1; --host / STAGEFLOW_BIND; image uses 0.0.0.0; Host/Origin stays localhost (SSH tunnel for remote).
  4. Container is the Host; -p 3847:3847; CLI is docker exec … sf ….
  5. Optional /workspace mount; no-mount MCP inline; A2A needs on-disk files.
  6. Checkout = local dir. Repository = GitHub owner/repo + required ref. XOR. Host clone cache + Worktree per RunId under ~/.stageflow. PR is a stage (gh). GITHUB_TOKEN on container env only.
  7. MCP is the Harness (inline JSON pipeline = create+run, no rerun). A2A = on-disk publications only.
  8. Skills on start_run as name→files for that Run.
  9. Fat agent image later (Node ≥22.19, git, bash, gh). Not a sandbox. Dockerfile after Host features.
  10. Agreed order: bind + PID1/no-browser + HOME + headless creds → repository/worktree → start_run skills → Dockerfile.

Explicit non-copies from Intentic

  • Hosted tunnel hub and vanity reachability
  • Google identity, member tiers, trust-on-first-use owner
  • Nested Docker engine, SYS_ADMIN, host docker.sock
  • Conversation / fleet UI; SDLC-as-product framing (“land”, chores as primitives)
  • Remote runners before single-container Host is solid
  • Full sandbox.toml / capability marketplace—borrow rules (unknown keys error), not the artifact
