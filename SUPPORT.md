# Support

Stageflow is personal open-source software maintained by a solo developer. Support is best-effort.

## Getting Help

**GitHub Issues** is the primary channel:

[https://github.com/tejasghutukade/stageflow/issues](https://github.com/tejasghutukade/stageflow/issues)

Use issues for:

- Bug reports
- Feature requests
- Questions about YAML authoring, CLI usage, or CI integration

Before opening an issue, check existing issues and the [documentation](docs/README.md).

## What to Include

Help us help you faster:

1. **Stageflow version** — `sf --version` or `npm list -g stageflow`
2. **Node.js version** — `node --version` (requires ≥ 20)
3. **What you tried** — commands, YAML snippets, or CI workflow steps
4. **What happened** — error output, exit code, or unexpected behavior
5. **What you expected**

For operator console or run failures, include relevant logs from `.stageflow/runs/<runId>/` if possible (redact secrets).

## Response Expectations

- No SLA or guaranteed response time
- Issues are triaged when time allows
- Pull requests with tests or clear repro steps are appreciated

## Security

Do not report security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

## Commercial Support

Stageflow is not a commercial product. There is no paid support tier.
